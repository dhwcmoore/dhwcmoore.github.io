Proof-Carrying Exactness

Separates an untrusted certificate generator from a pure verifier and independently re-checks four verdict classes before any result is released.

Built

  • Pure certificate verifier with no search or discovery dependency.
  • Separate untrusted generator for EXACT, UNDERDETERMINED, OBSTRUCTED and INADMISSIBLE.
  • End-to-end assessment interface and CLI with fail-closed handling of malformed input, generation failure and verifier rejection.

Assurance value

  • Generator cannot release a certificate that the production verifier rejects.
  • Assessment layer verifies again rather than trusting the generator's internal gate.
  • Includes tampered-certificate and malicious-generator rejection demonstrations.

Boundary: the public end-to-end demonstration currently covers the generic affine-rational pipeline. A region-native adapter and real regional evidence path are not claimed.

Structural Admissibility Library

Formalises when an observation interface preserves the distinction required by a safety predicate, and when no downstream classifier can recover information that the observation has already lost.

Built

  • 41 Rocq source modules covering factorisation, refinement, collapse, runtime monitoring and three case-study domains.
  • Extracted OCaml monitor and certificate-checking components.
  • Runtime states and typed engineering actions for review, rejection, restriction or observation refinement.

Formal status

  • Zero admitted lemmas reported in the public repository.
  • Eight named axioms, each documented rather than hidden.
  • Case studies cover consensus, GPU memory observation and physical-system sensing.

Boundary: the extracted components form a verified core. The repository does not claim a production dashboard, issue tracker or complete deployed safety system.

Proof-Carrying Audit Warrants

Checks whether admitted evidence still warrants a specific audit claim under declared policy and conditions, rather than treating old audit conclusions as permanently authoritative.

Built

  • Four logical verdicts: WARRANTED, DEFEATED, UNDERDETERMINED and INADMISSIBLE.
  • Declarative semantics connected to an executable classifier by soundness and completeness results.
  • Extracted checker, CLI and 14 published fixtures across three source-gated audit cases.

Verification discipline

  • coqchk clean with no admitted obligations or project axioms reported.
  • Preservation and defeat under evidence extension are formalised separately.
  • Evidence admission, claim evaluation and failure witnesses remain explicit.

Boundary: the checker verifies a formal warrant judgement over the evidence ledger it receives. It does not establish that supplied evidence is true, complete, or that an AI system is safe.

Engineering principles

Systematic bug prevention starts at the claim boundary

These rules are simple, but they are where many silent failures begin.

If a tolerance matters, state it.A numerical tolerance is part of the specification, not an implementation detail to be guessed later.
If the observation loses the distinction, stop.No downstream intelligence can recover a distinction that is absent from the available observation.
If the whole matters, check the whole.Local success or pairwise agreement does not imply a global property unless that implication has itself been established.
If data are transformed, prove what survives.Compression, projection, aggregation and discretisation may preserve one conclusion while destroying another.
If the generator says it is correct, that is still the generator speaking.Independent assurance requires an independently specified check, not a second assertion from the producing component.
If the evidence is insufficient, say insufficient.An underdetermined result is preferable to a confident answer unsupported by the declared evidence.
